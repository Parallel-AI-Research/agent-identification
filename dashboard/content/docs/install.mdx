title: Install
description: Report agents from your server, with nothing added to your pages.
---

Your server reports agents from the requests it already receives, and your pages stay as they are. Your product page in the dashboard has these snippets with your own site ID filled in. The site ID is public, so it's safe to commit.

Every report needs your server secret, so set `AGENT_ID_SITE_SECRET` wherever your server runs. Never put it in browser code.

## What your server reports

- **Signed requests.** `reportSignedRequest()` passes on a request that carries a [Web Bot Auth](/docs/signed-agents) signature, and the collector checks it against the signer's published keys.
- **User agents that name an agent.** `reportRequestSignals()` reports a request whose user agent names an AI agent or crawler, such as `ChatGPT-User` or `ClaudeBot`, or a headless browser. These are [signals](/docs/activity#automation-signals), not proof, because anyone can send them.

Both skip ordinary requests without a network call, as well as scripts, styles and images, so a page load counts once. Neither throws or slows the response. You can also [report actions](/docs/activity#actions-from-your-server), such as an order placed, from wherever your server handles them.

## Next.js

```sh
npm install https://parallel-agent-identification.vercel.app/downloads/parallel-research-agent-identification-0.5.0.tgz
```

Add this to `proxy.ts`, which runs on Node.js. If you already have one, add the lines to its function. Its `matcher`, if it has one, decides which requests are checked.

```ts
// proxy.ts
import {
  reportRequestSignals,
  reportSignedRequest,
} from "@parallel-research/agent-identification/server";
import type { NextFetchEvent, NextRequest } from "next/server";

const agentId = {
  apiUrl: "https://parallel-agent-identification.vercel.app",
  siteId: "YOUR-SITE-ID",
  secret: process.env.AGENT_ID_SITE_SECRET!,
};

export function proxy(request: NextRequest, event: NextFetchEvent) {
  // Next.js changes the request's URL to localhost, and an agent signs the host it asked for.
  const url = new URL(request.url);
  url.host = request.headers.get("host") ?? url.host;
  event.waitUntil(reportSignedRequest(request, { ...agentId, url: url.href }));
  event.waitUntil(reportRequestSignals(request, agentId));
}
```

Next.js 15.5 calls the file `middleware.ts`. Name the function `middleware` and set the Node.js runtime in its config: `export const config = { runtime: "nodejs" };`. The server package needs Node.js, so it can't run in the Edge runtime, which is middleware's default.

## Node.js

The same two calls work in any Node.js request handler. With Express:

```ts
import {
  reportRequestSignals,
  reportSignedRequest,
} from "@parallel-research/agent-identification/server";

const agentId = {
  apiUrl: "https://parallel-agent-identification.vercel.app",
  siteId: "YOUR-SITE-ID",
  secret: process.env.AGENT_ID_SITE_SECRET!,
};

app.use((req, res, next) => {
  void reportSignedRequest(req, agentId);
  void reportRequestSignals(req, agentId);
  next();
});
```

If something in front of your server changes the `Host` header, pass the URL the visitor requested to `reportSignedRequest()` as `url`. An agent signs the host it asked for, so a signature checked against another host fails.

## Any other server

Send the same reports as server-to-server requests, in the background so visitors never wait. When a request has `Signature` and `Signature-Input` headers, send its method, the URL the visitor asked for, and the headers it signed: those two, `Signature-Agent`, and any other header named in `Signature-Input`.

```sh
curl https://parallel-agent-identification.vercel.app/v1/signatures \
  -H "Authorization: Bearer $AGENT_ID_SITE_SECRET" \
  -H "Content-Type: application/json" \
  -d '{"siteId":"YOUR-SITE-ID","request":{"method":"GET","url":"https://your-site.example/pricing","headers":{"signature":"…","signature-input":"…","signature-agent":"…"}}}'
```

When a request's user agent names an AI agent, report it as a signal. Use a new UUID for each one, and send the same one again to retry:

```sh
curl https://parallel-agent-identification.vercel.app/v1/signals \
  -H "Authorization: Bearer $AGENT_ID_SITE_SECRET" \
  -H "Content-Type: application/json" \
  -d '{"siteId":"YOUR-SITE-ID","signals":[{"id":"8d4f…","signal":"agent_user_agent","detail":"ChatGPT-User","occurredAt":"2026-11-05T12:00:00Z"}]}'
```

The tokens the Node.js package looks for are `ChatGPT-User`, `OAI-SearchBot`, `GPTBot`, `Claude-User`, `Claude-SearchBot`, `ClaudeBot`, `Perplexity-User`, `PerplexityBot`, `MistralAI-User` and `DuckAssistBot`. A headless browser is `headless_browser` with the detail `HeadlessChrome`.

## Check it works

Your server only reports agents, so request a page as a headless browser:

```sh
curl -A "HeadlessChrome/1.0 (install check)" https://your-site.example/
```

**Status** on your product page then says **Receiving events** and when your server last reported. See [troubleshooting](/docs/troubleshooting) if it doesn't.

## What it doesn't see

Server reporting sees what your server receives. An agent that neither signs nor names itself, such as one working through a person's own browser, looks like any other visitor and stays unknown. Reports that carry no session are counted on the Activity page apart from sessions.

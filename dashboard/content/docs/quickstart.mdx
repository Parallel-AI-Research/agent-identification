You can read these docs without an account. You'll need one to add a product, because each site ID belongs to its owner.

## 1. Add a product

[Create an account](/sign-up) and confirm your email. In the [dashboard](/dashboard), choose **Add product**, then enter a name and the origins your product runs on.

Origins must be exact. `https://example.com` and `https://www.example.com` are separate origins, so list both if you use both. A signed request only verifies for one of these origins.

## 2. Save your server secret

The dashboard shows your server secret once. Save it somewhere private, then set it as `AGENT_ID_SITE_SECRET` wherever your server runs. Only your server should ever hold it, and if you lose it, you can rotate it for a new one.

## 3. Report from your server

Your product page has snippets with your own site ID. Install the package:

```sh
npm install https://parallel-agent-identification.vercel.app/downloads/parallel-research-agent-identification-0.6.0.tgz
```

Then add two calls where your server handles requests. In Next.js, that's `proxy.ts`:

```ts
// proxy.ts
import {
  reportRequestSignals,
  reportSignedRequest,
} from "@parallel-research/agent-identification/server";
import type { NextFetchEvent, NextRequest } from "next/server";

const agentId = {
  apiUrl: "https://parallel-agent-identification.vercel.app",
  siteId: "YOUR-SITE-ID",
  secret: process.env.AGENT_ID_SITE_SECRET!,
};

export function proxy(request: NextRequest, event: NextFetchEvent) {
  // Next.js changes the request's URL to localhost, and an agent signs the host it asked for.
  const url = new URL(request.url);
  url.host = request.headers.get("host") ?? url.host;
  event.waitUntil(reportSignedRequest(request, { ...agentId, url: url.href }));
  event.waitUntil(reportRequestSignals(request, agentId));
}
```

Both calls skip ordinary requests without a network call, and neither throws or slows the response. See [Install](/docs/install) for other Node.js servers and for any other language, or hand the job to your [coding agent](/docs/coding-agents).

## 4. Add the page script

Add this tag to every page, through your shared layout or template. It draws nothing. It gives each visit a session with its page views, and reports a browser that shows automation, so you can see what an agent did on your site.

```html
<script
  defer
  src="https://parallel-agent-identification.vercel.app/sdk/v0.6.0/agent-id-track.js"
  data-site="YOUR-SITE-ID"
></script>
```

In a Next.js app, put it in your root layout with `next/script`. See [the page script](/docs/install#the-page-script) for that, for bundled apps, and for its options.

## 5. Check it works

Open a page that has the page script. Then, because your server only reports agents, make a request that looks like one. With your site running, request a page as a headless browser, at its local address if it isn't deployed yet:

```sh
curl -A "HeadlessChrome/1.0 (install check)" https://your-site.example/
```

On your product page, **Status** changes from **Waiting for installation** to **Receiving events**. It says when your server last reported, and when your pages last reported from each origin. The collector records your check as one request showing automation. Copying a snippet doesn't count. Only a report the collector accepts does.

If something is refused, Status says what and how to fix it:

- **A server secret the collector doesn't accept:** check that `AGENT_ID_SITE_SECRET` matches your current secret.
- **A page on an origin you haven't listed:** the page script only reports from your product's origins. Add the origin if the site is yours.

Anyone can send a request claiming any origin or secret, so a refusal shows what reached the collector, not who sent it.

## 6. Verify your domain

This step is optional and never blocks your data. On your product page, add the DNS record shown, then choose **Check DNS record**. Until then, the domain is labelled as unverified.

# Version 1 contract

Collection declares a choice; it never proves identity or grants permission. Origin checks constrain browser use, not non-browser attackers. Public site IDs are public configuration.

Base API URL excludes `/v1` (e.g. http://127.0.0.1:4310). Browser requests use credentials: omit. Origin must exactly match an allowed origin of the configured site. HTTPS origins only, except localhost/127.0.0.1 development. CORS explicit origins, Vary: Origin, no cookies, allow Authorization, Content-Type, X-Agent-Site, GET/POST/DELETE/OPTIONS. All responses Cache-Control:no-store; body max 8KiB. JSON requests require application/json.

- POST /v1/sessions JSON `{siteId, bindingContext?}` ->201 CreatedSession (src/protocol.ts). sessionToken opaque random256bit, stored only hashed server-side. Anonymous sessions valid30minutes. Optional bindingContext minted by customer's server, signed with its per-site secret. Tokens never in URLs/logs.
- GET /v1/sessions/current ->200 SessionStatus, headers Authorization:Bearer sessionToken, X-Agent-Site:siteId. Exact site/origin/token/expiry/revocation verification.
- POST /v1/declarations JSON `{choice,requestId}` with same headers ->200 RecordedDeclaration. requestId UUID, idempotent per session; same key with different choice ->409. One final choice per session; different new choice after acceptance ->409. Site and origin from bound server session, never body. Choice any of ai_assistant/person/prefer_not_to_say.
- DELETE /v1/sessions/current ->204 invalidates session token. Evidence retained for retention period. Idempotent on already closed token, not unknown/wrong site/origin. reset() invalidates then starts a new session.
- GET /v1/events?siteId=...&limit=100 -> JSON `{events:[{id,siteId,origin,sessionId,choice,evidence,createdAt}]}`. Authorization:Bearer site's secret, server-to-server only (no CORS). Limit1–1000; newest first. No token/bindingContext/bindingHash/private secret fields.
- POST /v1/verify JSON `{siteId,origin,sessionBinding,receipt}` -> `{valid:true,sessionId,eventId,choice,evidence:"self_reported"}`. Server-to-server only, no CORS, Authorization:Bearer site's secret. Host supplies its actual active session binding. Checks signed claims and the stored declaration, expiry and revocation. Public helper `verifyDeclarationOnline(receipt,{apiUrl,siteId,origin,secret,sessionBinding,now?,fetch?})` fails closed. Offline `verifyDeclaration` only verifies signed claims and cannot observe subsequent revocation.
- GET /health -> `{ok:true,version:"0.1.0",storage:"postgres"|"memory"}` (no secrets); production must reject memory store.
- POST /internal/prune (also GET for authenticated Vercel cron), Bearer PRUNE_SECRET, deletes expired retained data and old rate buckets. Retention7days by default. Request handling also opportunistically prunes bounded stale records. No raw visitor IP stored; rate buckets hashed per site+client key, expires quickly.

SiteConfig `{id:string, origins:string[], secret:string}` in server-only AGENT_ID_SITES JSON; secret minimum32characters. Anonymous visitor session is site+origin scoped. Customer site servers derive bindingContext from their own active session using createBindingContext; never trust a binding from a browser request. Server helper verifyDeclaration must require expected siteId, origin, secret, actual sessionBinding and currenttime. Unbound anonymous receipts MUST be rejected by this helper. Accepted classification does not authorize action on its own: customer still checks account permissions.

JWT-like HMAC-SHA256 signed contexts/receipts with purpose separation, strict claims and expiry. Bindings opaque server-derived strings, hashed for stored claims. Never put personal data in bindings. Context short-lived (max15min); declaration receipt lifetime no longer than collector session and context where bound. Shared server helpers live src/server/index.ts. Backend can import helpers with additional internal mint/verify exports from src/server/tokens.ts (not public package entry).

## Browser SDK

`init(options)` synchronous returns `Widget` with ready:Promise<SessionStatus>, getState(), reset():Promise<SessionStatus>, destroy():void. Options: container:HTMLElement|string; siteId; apiUrl; mode?:optional|required (defaultoptional); gate?:HTMLElement|string; styleUrl? (default apiUrl+/sdk/v0.1.0/agent-id.css); bindingContext?:string|(()=>Promise<string>); storage?:session|memory (defaultsession); onRecorded?(RecordedDeclaration); onError?(Error). getState returns status|null. destroy restores original gate inert state; never submits/clears server record. reset revokes oldtoken and createsnew; cannot falsely indicate reset while revoke failed. Async results after reset/destroy ignored. No auto-answer, no webdriver/fingerprints/page URLs/credentials collected.

Widget uses ShadowDOM and external stylesheet; retry/error status is outside any supplied gate. Required mode gates only explicitly supplied DOM container using inert until server confirms any choice. Gate cannot contain widget. Without gate use onRecorded callback forhostUI; explain UI-only clearly. Buttons accessible namedlabels; aria-live forstatus/errors; keyboardworks. Keep minimal neutral UI consistent with research wording. No arbitrary HTML injection.

Session storage key includes API URL+site+origin+binding-context identity (do not persist rawcontext). Restore verifies with server before unlocking. Token scoped to anonymous tab session; memory fallback when storage blocked. Binding callbacks support login changes via reset; document reset on logout. Idempotent init on samecontainer; reject conflictingconfiguration instead of duplicating widgets/listeners.

Script build `agent-id.js` IIFE sets window.AgentIdentification. Reads its own script dataset: data-site, data-api(defaultscriptorigin), data-target(optional autoappendcontainer), data-mode, data-gate, data-storage. No secret. PlainHTML<script defer src=... data-site=... data-mode=...>. Script styling separateversioned CSS. ESM package samecore. React `<AgentIdentification ...options>` mounts owncontainer, exposes onRecorded/onError; cleanup on unmount, no server DOM access.
